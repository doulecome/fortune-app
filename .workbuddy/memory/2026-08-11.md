# 2026-08-11 工作日志

## 动效打磨 v13（用户：点击页面切换很不自然）
- **问题根因**：顶部 tab/分类点击触发 `switchPanel`——旧面板先 0.18s 渐隐，再换入新面板；而新面板 `.panel.show` 入场用的是「从下方升起」类动画（`rise`: translateY(14px)+scale(.99)；暗色/断点 `scrollUnfurl`: scaleY(.94) 从顶部展开；`kResult`: 轻上移），加上 `.tab.active` 回弹 `tabPop`(scale .9→1.05→1)。组合观感=「旧内容先淡掉→空一拍→新内容从下方飘上来」，不是就地替换，故割裂不自然。
- **修复（仅动入场属性/衔接，不改叙事与内容）**：
  1. 所有 `.panel.show` 入场统一改**就地淡入**：`rise` → `translateY(6px)` 去 scale、时长 .5s→.42s；`scrollUnfurl` → 去 `scaleY(.94)` 顶部展开、改 `translateY(6px)`；`kResult` 本就轻（translateY 3px）保留。
  2. `.tab.active` 回弹收敛：`tabPop` `.9→1.05→1` 改 `.94→1.03→1`（减少弹跳）。
  3. `switchPanel` 旧面板淡出 `.18s→.15s`、`setTimeout 180→150`ms，新旧衔接更利落。
- **验证**：build 785KB，三套门禁全绿（运行时 0 错误；八字2386/紫微1438/奇门913/塔罗967/称骨456；fx-draw 92、唯一延迟 79 种、二次揭幕 -0.5s/1500ms ✅）。
- **经验**：① 标签/面板「切换」的自然感来自「就地替换」（opacity 淡入 + 极小 ≤6px 位移），绝非「升起/展开/弹入」类带方向的动画——后者像开弹窗而非切标签。② 真 cross-fade（新旧同位置重叠淡入）最无缝，但需给面板加 `.stage` wrapper 改 HTML 结构、有高度跳动风险，本案未采用，留作可选；当前串行就地已明显自然。③ tab 回弹幅度过大会显廉价，≤1.03 更克制。

## 动效打磨 v15b（用户：每个 tab 的切换很卡顿）
- **真凶 = `transition:height`**：v15 为消除高度跳动，给 `.stage` 加了 `transition:height .26s`。但 `height` **不是合成属性**，动画它每帧触发整块面板（八字 2386字+大 SVG）的 layout 重排（layout thrash）——这正是"每个 tab 切换都卡"的持续性卡顿源。正常分支的 `inkSwirl` 在 v15 重写时已移除，非主因。
- **修复**：cross-fade 改为**只靠 `opacity`（GPU 合成、零重排）**；`.stage` 切换期间锁旧高（`height=h0` + `overflow:hidden` 防溢出覆盖），**绝不动画 height**；结束（290ms）后一次性释放高度到新面板自然高度 `height=''`（一次静态布局，无动画、不卡帧）。代价：若新旧面板高度差大，切换完成后容器高度有一次静态调整（非持续卡顿，可接受）。
- **验证**：build 787KB，三套全绿（0 错误；八字2386/紫微1438/奇门913/塔罗1012/称骨456；fx-draw 92、79 种延迟、二次揭幕精简 ✅）；Grep 复核 app.js 仅剩两处静态 `stage.style.height`（锁/释放），无 `transition='height'`。
- **经验**：① **非合成属性（height/width/top/margin）原则上不要做 transition/animation**——它们每帧触发 layout，重内容下必卡。**但有例外**：当参与布局的“重内容”已 `position:absolute` 脱流时，对这些内容的**父容器**做 height 动画，每帧只重排“空容器 + 底部 footer”（轻量），不会重排沉重 SVG，丝滑。cross-fade 高度差的正确做法 = 切换期间新旧面板都 absolute、容器 `height` 从 h0 平滑 transition 到 h1、结束后释放到 auto（=h1，无跳）。反例（v15b）：锁旧高、结束后一次性释放 → 仍有跳变，用户感知为“卡顿”。② 诊断"每个 X 都卡"类反馈时，优先找该操作新增的**非合成属性动画**（layout thrash），而非又去砍效果。③ 交付前 Grep 复核"无残留 height transition"已成固定动作。


- **流畅度优化 v15c（用户：页面长度有差别导致看起来很卡顿）**：根因是 v15b“锁旧高→结束后释放”在面板高度差大时仍有一次静态跳变（用户感知为卡顿）。修复 = 让切换期间两面板都保持 `absolute`（脱离文档流），`.stage` 容器高度 `transition:height .26s` 从旧高 h0 平滑伸缩到新高 h1；因面板脱流，高度动画每帧只重排空容器+底部 footer，不碰沉重八字 SVG，故丝滑；结束（290ms）后清除行内样式→自然高度 h1（与动画终点一致，零跳变）。同时给 stage 加/去 `switching` 类驱动 `.stage.switching > .panel.prev{position:absolute}`。需 `stage` 为 `position:relative`（已有）、`.stage > .panel.show` 的 `panelIn` 入场保留（opacity+6px，合成）。经验落成：非合成属性动画的禁忌**仅在重内容在流内时成立**；重内容脱流后，容器高度动画安全。
- **验证**：build 791KB，三套全绿（0 错误；八字2386/紫微1438/奇门913/塔罗1008/称骨456；fx-draw 92、79 种延迟、二次揭幕 -0.5s/1500ms；暂停态 fx-hold=0 ✅）。编辑器对 app.js 的 Read/Edit 工具偶发内部报错（"file_path expected string"/"startsWith"），但改动实际已落地（node 核对确认），故改用 python heredoc 直接补丁 + node 复核；属工具环境偶发问题，不影响产物。

## 动效打磨 v16（用户：高度伸缩还是太丑了 → 恒定高度 stage + 内部滚动 + 纯 cross-fade）
- **问题**：v15c 的"双面板绝对脱流 + 容器 height .26s 平滑伸缩"技术上丝滑（重 SVG 不重排），但**观感仍是"抽屉伸缩"**——用户明确反感"高度伸缩"这种带方向的尺寸变化，与技术是否流畅无关。
- **解法（终极：让高度根本不变）**：`.stage` 改为**恒定高度容器** `height:min(86vh,960px);min-height:460px;overflow:hidden`；每个 `.panel`（`> .panel` 与 `.panel.show`）`height:100%;overflow-y:auto` **内部滚动**。切换时 `switchPanel` 彻底**不做任何 height 测量/动画**：新面板 `position:absolute;inset:0;z-index:3` 原位覆盖、`p.style.animation='none'` 关入场、`opacity 0→1` 过渡 .26s；旧面板 `relative` 原位、`opacity 1→0` 过渡。二者纯透明度交叉淡出；`.stage` 高度恒定 → 底部 footer 与页面布局纹丝不动，彻底无伸缩、无跳变、无重排。
- **代价（可接受）**：高面板（八字 2386 字）现在在卡片内滚动而非整页滚动；矮面板（称骨 456）下方留白由恒定高度吸收，但恒定高度≈一屏，留白很小。整体从"整页滚"变"卡片内滚"，更像 App，但换来了切换零抖动。
- **验证**：build 791KB，三套全绿（运行时 0 错误；八字2386/紫微1438/奇门913/塔罗956/称骨456；fx-draw 92、79 种延迟、二次揭幕 -0.5s/1500ms、fx-hold 0；CSS 层叠无陷阱 ✅）。
- **经验**：① 当各 tab 面板长度差异悬殊且用户反感"任何带方向的尺寸变化"时，**唯一能彻底消除高度差观感的做法 = 恒定高度容器（固定高 + 内部滚动）**，而非"脱流 + 动画 height"（再丝滑也是伸缩）。② 非合成属性禁忌的"脱流例外"只解决性能卡顿，**解决不了审美**——用户要的是"不动"，不是"动得顺"。③ 恒定高度 stage 下 cross-fade 用"新 absolute inset:0 覆盖 + 旧 relative 原位 + 纯 opacity"最干净，记得给新面板 `z-index` 压在上层（DOM 顺序不一定新在上）。
