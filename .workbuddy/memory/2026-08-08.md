## 修复「展开完整解读」不居中
- 用户反馈按钮不水平居中。先用 jsdom `getComputedStyle` 验证级联：folded=`translateX(-50%)`、open=`fit-content+margin:auto` 在级联层"都居中"，但真实浏览器里这两技巧之一失效（疑似 `width:fit-content`+block+auto-margin 或 transform 的浏览器差异），故换成零依赖兜底的经典写法。
- 修复（ui.html）：① 折叠态 `.fold-toggle` 改写为 `.result .fold-toggle`（提高特异性锁死 `width:fit-content`，杜绝 `.btn{width:100%}` 抢成满宽条），居中改用 `position:absolute;left:0;right:0;margin:0 auto`（经典绝对定位居中，任意宽度都成立，不依赖 transform）。② 展开态 `display:table;width:auto;margin:14px auto 0`（比 `block+fit-content` 更通用，所有浏览器都居中）。③ 按钮本身补 `text-align:center`。
- 验证：jsdom 级联复核 folded/open 两个状态均 `margin-left:auto;margin-right:auto` + `transform:none`；`build.js` 重建 → CSS 400/400 平衡 → `test_real.js` 0 运行时错误 / 19 标签 / 八字·紫微·奇门均有内容。
- **经验**：① 用 jsdom `getComputedStyle` 验证 CSS 级联比肉眼推演可靠——能直接看到 resolved 的 width/margin/position/transform，快速区分"级联错"还是"真实浏览器渲染差异"。② 居中优先用「不依赖 width 的写法」：`position:absolute + left:0;right:0;margin:0 auto`（任意宽都居中）或 `display:table + margin:auto`（比 block+fit-content 更通用）。③ `left:50%;transform:translateX(-50%)` 居中依赖 width 为 shrink/fit-content；一旦被 `width:100%` 抢成满宽，按钮就变成"左缘贴底满宽条"看似不居中——根源是特异性同级靠源码顺序决胜，用更高特异性（如 `.result .fold-toggle`）显式锁 width 更稳妥。

## 下拉箭头去金（收尾）
- 用户："顺手把那处下拉箭头也调成墨色"。`select` 下拉箭头是内联 data-URI SVG（`ui.html:186` `stroke='%239c7b46'` 金）。改：浅色 `stroke='%235b554a'`（墨）；并补深色——深色 `body.theme-dark select` 原用 `background:var(--glass-strong)` **简写会清空 `background-image`（箭头消失）**，改为 `background-color:var(--glass-strong)` + 单独 `body.theme-dark select{background-image:...stroke='%23b8ab90'...}` 奶油箭头。
- **经验（CSS 坑）**：`background:` 简写会重置 `background-image` 为 none。深色主题覆盖带箭头的 `select` 时，必须用 `background-color:`（而非 `background:`）保留箭头，再单独设 `background-image`。SVG data-URI 内 `stroke` 不能引用 `var()`，需按主题写两个硬编码色（浅墨 `#5b554a`/深奶油 `#b8ab90`）。
